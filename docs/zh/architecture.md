# 系统架构

[English](../en/architecture.md) | [中文](architecture.md)

Proactive AI 是一个小型 TypeScript monorepo，由模型无关的核心层和交互式 Web 参考实现组成。

```text
proactive-ai/
├── apps/
│   └── demo/                 # Next.js/vinext 时间线实验室
├── packages/
│   └── core/                 # 协议、引擎、规划器和模型适配器
├── docs/
│   ├── en/
│   └── zh/
└── paper/                    # ACM LaTeX 论文
```

## 运行流程

```text
独立用户消息到达 ─> 协调器 ─┐
对话起搏 ───────────────────┼─> 确定性引擎 ─> 规划器上下文
队列到期 ───────────────────┘                   │
                                  ├─ 确定性 Demo 规划器
                                  └─ 服务端模型适配器
                                           │
                               OpenAI-compatible /chat/completions
                                           │
                              OpenAI · Qwen · LiteLLM · 兼容接口

规划 JSON -> Schema、队列与联系策略验证
          -> 原子状态转移 -> 可见消息 + 修改后的状态
```

`packages/core` 负责所有时间与队列状态决策。大模型只能提出计划，不能直接发送消息、修改持久化状态或计算权威时间戳。

## 核心模块

- `protocol.ts`：定义严格的规划器输出 Schema 与可移植 JSON Schema；
- `engine.ts`：实现独立消息到达、决策合并、过时快照拒绝、逻辑时间、队列生命周期、原子执行与关闭式失败恢复；
- `demo-planner.ts`：为测试与演示提供可重复的中英双语场景；
- `openai-compatible.ts`：调用 Chat Completions、请求结构化输出、对错误格式重试一次，并在本地验证结果。

## Demo 模式

引擎中的时钟与规划器仍相互独立，用户界面则提供两种清晰分开的体验。“场景演示”通过播放控件驱动固定故事经过实际引擎执行，不提供输入框；“真实对话”使用已配置模型，默认跟随真实时间，模拟时间收在高级控制中。两种体验的状态不会混合。

场景规划器无需模型调用即可提供可复现提案，核心包的确定性规划器继续用于协议测试。真实对话在首条消息后开始自动调度，将真实时间会话保存在独立浏览器存储中，并在页面恢复后把错过的唤醒合并为一次基于最新情境的判断。

真实对话把规划器上下文发送到 `/api/plan`。服务端从环境变量读取凭据，调用配置的模型，并只返回已经验证的时间计划。API Key 永远不会发送到浏览器。切换回场景演示会卸载模型会话并停止其自动调度。

浏览器中的真实时间驱动用于展示页面打开期间的现实时间语义。可靠的后台发送仍属于部署层问题：生产服务还需要持久化状态、可靠调度器和外部消息发送通道。

## 模型边界

核心 `Planner` 是一个从 `PlannerContext` 到 `PlannerOutput` 的函数，这个小接口就是稳定边界。默认远程实现使用 OpenAI-compatible Chat Completions，因为 OpenAI、Qwen 与 LiteLLM 都支持这种形式。未来可以增加 Responses API 适配器，而不修改引擎或 Demo。

## 确定性层的职责

以下工作由引擎而非模型负责：

- 当前时间和相对延迟换算；
- 唯一 ID 与稳定排序；
- 将相邻到达的消息合并为一次决策快照；
- 输入在推理期间变化时拒绝旧候选计划；
- 判断哪些行动已经到期；
- 按现实时间安排唤醒，并在页面挂起后执行一次追赶判断；
- 验证所有到期行动都被恰好处理一次；
- 原子化执行全部队列修改；
- 失败恢复与重试时间；
- 有界沉默截止时间与外部主动联系开关；
- 最终发送消息。

这一边界降低了切换模型提供商的风险，也使研究原型在模型输出仍具有随机性时，依然保持可重复的系统语义。

## 部署中的用户控制与隐私

将原型用于实际服务时，部署方还需提供以下控制；这些是部署要求，而非当前 Demo 已全部实现的功能：

- 用户能够暂停主动联系、查看和撤销未来行动。联系截止时间不能越过用户授权、免打扰时段、频率限制或领域安全规则。
- 待发送内容、记忆和行动理由可能包含个人信息。应限制数据保留时间与检索范围，对持久化数据采取加密和访问控制，并提供检查和删除入口。行动理由只需保留简短的操作依据，不应要求模型生成或持久保存隐藏推理。
- 界面明确标识系统的 AI 身份。拟人化表达不应冒充真人，或通过激发负罪感向用户施加回应压力。
