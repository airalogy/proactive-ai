# 核心概念

[English](../en/core-concepts.md) | [中文](core-concepts.md)

## 把对话理解为时间线

Proactive AI 不把对话理解成一组必须完成的问答轮次，而是将其视为一条持续发展的时间线，其中包括：

- 用户发来的零条、一条或多条消息；
- 用户与 AI 的沉默；
- AI 内部的周期性醒来；
- 立即发送和计划发送的消息；
- 记忆与待处理意图的变化。

用户消息是 AI 可以观察到的信息。它可以触发思考，但不要求 AI 立即作出可见回复。

## 消息到达与决策快照

用户每次点击“发送”都会产生一条独立、带时间戳的到达事件。消息到达会请求系统重新判断，但到达事件、模型调用和可见回复并不需要一一对应。短时间内相邻到达的消息，可以共同进入一次决策快照中的有序 `newUserMessages` 列表。

因此，“用户连续发送多条，AI 随后统一回复”可能有两种成因：AI 已经观察过较早的消息，并主动把回复推迟到未来；或者用户发送得更快，前一次模型推理尚未完成，新消息就已经到达。后一种情况下，旧快照产生的候选计划已经过时，协调器会在提交前将其丢弃，再基于全部尚未处理的消息重新规划。只有有效计划提交后，输入才被标记为已处理，有效的沉默计划也包含在内；失败或被丢弃的计划不更新处理标记，消息仍可进入后续判断。

## 统一决策循环

无论触发原因是用户发来新消息、对话起搏器到期，还是队列项目到达可执行时间，系统都运行同一套决策循环：

```text
触发事件
  -> 读取最新时间线、记忆、当前时间和待执行队列
  -> 判断已有计划是否仍然合适
  -> 保留、取消、修改、推迟或增加队列项目
  -> 发送当前适合发送的消息
  -> 根据需要安排未来的重新思考
```

因此，用户的新消息相当于一次中断。它可以使 AI 重新安排之前尚未发送的回复，而不是简单地在旧回合之后增加一个彼此独立的新回合。

## 可变的时间队列

未来行动使用 `not_before` 表示最早可以执行的时间，而不是承诺在某一秒准时发送。到达这个时间后，系统仍然需要根据最新上下文进行发送前检查。

```json
{
  "queue": [
    {
      "id": "message-123",
      "type": "send_message",
      "content": "我又想到一个可能重要的问题。",
      "not_before": "2026-07-31T15:02:00+08:00",
      "reason": "continue_current_thought"
    },
    {
      "id": "wake-456",
      "type": "reconsider",
      "not_before": "2026-07-31T20:00:00+08:00",
      "reason": "consider_following_up_on_the_user_plan"
    }
  ]
}
```

相隔几秒的连续表达可以使用提前生成的 `send_message`。时间较长的延迟通常更适合使用 `reconsider`，使 AI 届时根据最新上下文重新生成内容，避免发送已经过时的消息。

## 对话起搏器

对话起搏器保证 AI 将再次获得判断机会，但不要求 AI 在每次起搏后都必须说话。

每次醒来后，AI 可以：

- 继续保持沉默；
- 立即发送一条或多条消息；
- 增加、修改或取消计划消息；
- 安排未来的重新思考；
- 根据对话或记忆主动开始一个新话题。

## 有界沉默

原型已经实现可配置的有界沉默策略。截止时间之前，规划器仍可选择沉默；截止时间到达后，如果外部策略允许主动联系，确定性运行时只接受至少产生一条可见消息的计划。

这项策略与对话起搏器并不相同：起搏器提供再次判断的机会，截止时间则避免每次判断都以沉默结束。临时禁止主动联系不会清除截止时间；新的可见 AI 消息会把截止时间向后推进；用户关闭该策略时才会清除它。

## 行为原则

- **沉默是合法行为。** 看见消息并不产生必须回答的义务。
- **尚未说出口的话可以改变。** 未发送消息必须能够适应新的上下文。
- **时间也是上下文。** 延迟和沉默可能改变一条回复是否仍然合适。
- **主动需要理由。** 主动消息应当来源于对话、记忆或有意义的变化，而不是为了制造活跃感。
- **用户保持控制。** 主动行为应当可以查看、调整和撤销。
