# Demo 使用指南

[English](../en/demo.md) | [中文](demo.md)

Timeline Lab 将“理解机制的场景演示”与“使用大模型的真实对话”分开。两者均通过同一个时序引擎验证计划、修改队列并发送消息。

## 启动

需要 Node.js 22.13 或更高版本，以及 pnpm 11.20.0。

```bash
pnpm install
pnpm dev
```

打开 `http://localhost:3000`。“场景演示”无需密钥，也不会调用模型。启用“真实对话”请阅读[模型提供商](model-providers.md)。

## 场景演示

点击“播放”观看完整的面试故事，“暂停播放”停止自动推进，“上一步”或“下一步”按自己的节奏回看事件，“重新开始”重置场景。点击“上一步”会暂停播放，并恢复此前的聊天消息、队列、时钟、联系截止时间和决策记录；回看后可以继续下一步或恢复播放。初始状态下“上一步”不可用。最后一步结束后自动停止。切换语言会以所选语言重新开始场景。

五个步骤分别展示：

1. 两条独立的用户消息进入同一次决策。AI 先回应，并安排稍后的补充、一条准备建议和一次未来重新判断。
2. 五秒后，已经准备好的补充消息经复核后发送。
3. 距开始四十五分钟，用户告知面试取消，并希望先缓一缓。尚未执行的两项意图被撤销，已发送的消息保留在历史中。
4. 当天下午，对话起搏器在没有新输入时再次触发判断，AI 选择沉默。
5. 取消消息两天后，联系截止时间触发新的判断，AI 不再等待用户提问，而是主动重新联系。

几小时或几天通过明确标注的时间跳转压缩呈现。自动播放时，普通步骤停留两秒，取消计划这一步停留三秒，完整播放约十秒；最后保持结果画面，不自动循环。需要仔细阅读时可以暂停或单步查看。这些展示间隔与对话中的实际时间戳是两回事。聊天消息、队列状态与决策记录均来自引擎执行结果，不是视频或独立播放的假状态。候选计划来自固定场景规划器，因此此模式不提供自由输入框。

场景定义位于 [guided-demo.ts](../../apps/demo/app/components/guided-demo.ts)。核心包原有的通用确定性演示规划器仍保留供协议测试使用。

## 真实对话

配置模型后选择“真实对话”。只有此模式提供自由输入框，并默认跟随电脑的真实时间。空会话在用户发送首条消息前不会自动调用模型；对话开始后，队列到期或对话起搏可能在没有新输入时继续调用模型，这些请求会产生正常的 API 费用。

可以用“再加一条”和“逐条发送”准备快速连续发送的序列。其中每条消息都是独立到达事件，相邻到达可以共享一次决策快照。用户消息触发推理后，输入框仍可继续使用；新的输入会使旧候选计划在提交前失效。

“高级时间控制”中保留模拟时钟和手动推进按钮。模拟时间仍使用真实模型，一次推进可能触发多次付费请求；它的会话与真实时间会话分开。“有界沉默”卡片中的“暂停”限制自主可见消息，不停止模型判断或直接回复。需要停止自动调度时，请切换到“场景演示”或关闭页面。

预设场景不会进入真实模型上下文或真实会话存储。真实时间模型会话使用独立的浏览器存储键；旧版混合规划器的存储保留不动，也不会被自动导入。

## 真实时间行为

消息和队列保存 UTC 时刻，真实时间界面按电脑所在时区显示。在浏览器存储可用时，真实会话会自动保存。页面挂起后恢复时，引擎只会基于最新状态进行一次追赶判断，而不是逐次补演所有错过的起搏。

自动判断仅在“真实对话”处于活动状态且页面打开时运行。浏览器存储也可能不可用，因此这不是可靠的后台通知服务。生产部署需要把同一引擎接入持久化存储和后台调度器。

## 界面区域

- **对话流**：展示用户可见消息；场景中的虚构用户标为“示例用户”。
- **未来队列**：展示待执行和已解决的预备消息与重新判断行动。
- **演示控制区**：展示当前步骤、时间跳转与该步骤说明的机制。
- **有界沉默卡片**：展示联系截止时间；真实对话中还可控制自主联系许可。
- **决策记录**：位于同一演示区域的聊天与队列下方，随对话同步展示触发、队列修改、发送、失败与沉默。静态的协议说明放在完整演示区域之后。

## 界面翻译

用户可见文案统一放在 [app/i18n/en.ts](../../apps/demo/app/i18n/en.ts) 和 [app/i18n/zh.ts](../../apps/demo/app/i18n/zh.ts)，包括界面标签、演示对话、快捷场景与决策记录说明。组件通过统一入口引用文案，类型检查和测试保证两种语言的键与结构一致。新增界面文案时应同时补齐两个语言文件，不再在组件中编写语言分支。显示层翻译已知的引擎标签，不改写存储的记录或任意用户、模型原文；原始技术错误保留在可展开的详情中。论文共用的英文图与中英双语 Demo 界面分开维护。

## 验证

```bash
pnpm test
pnpm lint
pnpm build
```

离线测试会通过核心引擎执行完整的中英文演示，检查可复现重播和非法步骤顺序，确认场景演示没有输入框，并验证真实对话默认使用真实时间且高级控件折叠。原有引擎与模型适配器测试继续覆盖时序约束、输入协调、策略控制及结构化计划，不调用付费模型。
