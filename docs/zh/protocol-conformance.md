# 协议一致性轨迹

[English](../en/protocol-conformance.md) | [中文](protocol-conformance.md)

这些事件轨迹用于检查研究原型是否遵循[时序对话协议](protocol.md)。下表汇总事件序列及预期的状态变化，便于核查队列修改、发送条件和外部联系策略。

## 检查清单

| 性质 | 事件序列 | 预期结果 |
| --- | --- | --- |
| 消息数量可变 | 一次用户事件 | 即时消息和未来计划的数量均可为零项或多项 |
| 上下文中断 | 跟进已经排定；用户在发送前改变前提 | 相关意图被修改，过时文本不被发送 |
| 发送时验证 | 一项预备消息到达发送时点 | 只有依据当前上下文再次确认后才允许发送 |
| 稳定发送顺序 | 模型倒序接受多项到期行动 | 运行时按到期时间和稳定 ID 发送，不重复发送 |
| 主动沉默 | 对话起搏时缺少充分的发言理由 | 状态转移成功，但不产生可见消息 |
| 有界沉默 | 多次起搏均保持沉默，随后到达联系截止时间 | 截止时间前允许沉默；到期后的下一份合法计划必须产生可见输出 |
| 策略暂停 | 到达截止时间时禁止主动联系，随后恢复许可 | 暂停期间不产生自主输出；截止时间继续保留，并在允许联系后履行 |
| 输入合并 | 多条用户消息在短时间内分别到达 | 每条到达保持独立，但规划器在同一快照中观察其有序列表 |
| 推理中断 | 旧快照的规划尚未完成时又有消息到达 | 旧候选计划不产生输出，并基于全部未处理输入重新规划 |
| 无效计划 | 计划遗漏一项到期行动 | 不产生可见行动，并保留可恢复的到期项 |
| 计划冲突 | 结构合法的计划违反队列不变量 | 候选输出与修改均不生效；恢复规则可更新重试时间 |
| 失败输入恢复 | 用户触发的计划失败，随后发生定时重试 | 输入在有效计划提交前始终待处理；协调器不会连续空转重试 |
| 截止时间唤醒 | 联系截止时间早于常规起搏，且没有队列行动 | 起搏提前到截止时间，无需新用户输入即可请求判断 |

## 关键轨迹

在上下文中断轨迹中，初始事件创建一项预备消息和一次未来重新判断；随后到来的用户更新在二者执行前使其前提失效。下一次状态转移同时移除这两项意图，因此即使时间越过原定时点，也不会发送过时内容。这一结果来自未来行动的统一更新，而不依赖语言模型自行记得撤回先前表达。

其他轨迹检查候选计划被拒绝时的状态一致性，以及有界沉默与外部联系策略的关系。遗漏到期行动或提出冲突修改的计划不会产生候选输出或应用候选队列修改；恢复过程保留未处理输入和待执行行动，同时推进重试时间。联系截止时间之前的起搏可以继续沉默，截止时间到达后，单纯沉默的候选计划不能清除联系要求。外部策略可以推迟联系，但规划器不能借此绕过用户控制。

## 复现方式

在仓库根目录安装依赖后运行核心测试：

```bash
pnpm --filter @proactive-ai/core test
```

[引擎测试](../../packages/core/test/engine.test.ts)包含可复现的事件序列和状态断言；[模型适配器测试](../../packages/core/test/openai-compatible.test.ts)通过模拟响应检查结构化计划解析与错误处理，不调用真实模型，也不需要 API Key。

另提供有调用上限的[真实模型轨迹验证](model-providers.md#有调用上限的真实模型验证)。用户输入与事件时间由测试控制，候选计划则来自配置的模型；未观察到的行为会直接报告，不会通过脚本补造。普通测试不会调用付费 API。

若要在界面中观察消息和队列的变化，请按照 [Demo 使用指南](demo.md)中的模拟时间流程操作。
