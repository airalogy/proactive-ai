# 现有工作及其与 Proactive AI 的区别

[English](../en/related-work.md) | [中文](related-work.md)

最近调研日期：2026-07-31

本文将与 Proactive AI 最接近的学术研究、开源系统和商业产品放在同一框架下比较。它是一份初步的技术文献调研，不是完整的专利检索，也不构成最终的学术新颖性声明。

## 用于比较的 Proactive AI 模型

Proactive AI 不把对话理解成一组必须完成的“用户提问—AI 回答”轮次，而是将其视为一条持续发展的异步时间线。

每次思考时，AI 可能观察到用户新发送的零条、一条或多条消息。它可以保持沉默、立即发送一条或多条消息、将一条或多条消息放入未来队列，或者只安排未来再次思考，而暂时不生成最终措辞。

待执行队列是可变的。以下三种事件进入同一个重新规划循环：

1. 用户发送新消息；
2. 周期性的意识起搏器触发；
3. 队列项目到达最早可执行时间。

规划器随后可以保留、修改、推迟、取消、重新排序或增加待执行项目，再决定当前应该发送什么。

可以简化表示为：

```text
状态 S(t) = 对话历史 + 记忆 + 当前时间 + 待执行队列
事件 e(t) = 用户消息 | 意识起搏 | 队列到期

规划器 π(S(t), e(t))
  -> 当前行动 + 队列变更 + 下一次醒来时间
```

这个定义有意比宽泛的“主动 AI”更加具体。真正具有区分度的研究对象是：**可重新规划的对话时间队列**。

## 总体比较

| 工作 | 主要主动形式 | 如何处理时间 | 输出形式 | 与 Proactive AI 的区别 |
| --- | --- | --- | --- | --- |
| [StalemateBreaker](https://arxiv.org/abs/1604.04358)（2016） | 在当前对话陷入冷场时主动引入内容 | 当前对话状态 | 选择一条回复 | 没有自主唤醒和未来队列 |
| [主动人机对话 / DuConv](https://arxiv.org/abs/1906.05572)（2019） | 主动引导对话达到预设话题目标 | 对话轮次顺序 | 每轮一条回复 | 规划话题方向，不规划现实时间中的表达 |
| [When to Talk](https://arxiv.org/abs/1912.09879)（2019） | 判断 AI 应继续说话还是保持沉默 | 当前会话内的相对顺序 | 一条话语或沉默 | 没有长时间延迟和可变队列 |
| [Wait, I'm Still Talking!](https://arxiv.org/abs/2002.09616)（2020） | 用户的连续短消息似乎尚未结束时先等待 | 短时间的输入边界 | 等待或立即回复 | 判断用户是否说完，不规划 AI 未来的自主表达 |
| [Neural Generation of Dialogue Response Timings](https://aclanthology.org/2020.acl-main.221/)（2020） | 预测自然的语音回答时机 | 毫秒或秒级语音时序 | 带时机的语音回答 | 没有主动发起、起搏和队列重排 |
| [Generative Agents](https://arxiv.org/abs/2304.03442)（2023） | Agent 记忆、规划、反思并主动交谈 | 模拟世界中的日常时间 | 虚拟世界中的行为计划 | 不是人与 AI 的异步消息协议 |
| [Mind the Gap / GapChat](https://arxiv.org/abs/2310.15415)（2023） | 根据会话间隔选择更合适的话题 | 数小时至数月的会话间隔 | 新会话开始后的回答 | 时间是生成上下文，不是触发器或待执行计划 |
| [Inner Thoughts](https://arxiv.org/abs/2501.00383)（CHI 2025） | 形成不可见的内部想法，并在表达动机足够强时参与对话 | 实时、事件或轮次导向 | 选中的想法转化为一条话语 | 没有明确的、可修改的现实时间未来消息队列 |
| [X-TURING](https://aclanthology.org/2025.acl-long.293/)（ACL 2025） | 用双方都能连续发送带时间戳消息的 burst dialogue 表示长期对话 | 生成或评测文本中的时间戳 | 多条连续消息 | 表面形式最接近，但没有在线持久队列和用户中断后的重排语义 |
| [ProactiveAgent](https://github.com/leomariga/ProactiveAgent) | 周期醒来，判断是否回复，并动态确定下一次睡眠时间 | 现实时间中的睡眠—唤醒循环 | 每次肯定判断后立即生成一条回复 | 已有起搏器，但没有零到多条未来消息队列 |
| Character.AI、Replika、Nomi | 用户离开后仍可发送与上下文有关的消息 | 产品内部控制的通知节奏 | 闭源的主动消息生成 | 用户体验相似，但调度和重排机制并未公开 |

## 1. 混合主动与目标导向对话

混合主动对话早于大语言模型出现。它的核心问题是：当前由谁控制对话方向。当系统不只是回答最后一个问题，而是主动提供信息、提出澄清问题、切换话题或引导用户达到系统侧目标时，就可以称为主动对话。

### StalemateBreaker

[StalemateBreaker](https://arxiv.org/abs/1604.04358) 判断开放域对话是否陷入冷场，并从外部知识中引入新内容。它的流程分别决定何时需要新内容、应该引入什么内容，以及如何对候选回复排序。其贡献是在一次正在进行的会话中主动维持话题。

这里的“何时”是对话状态判断，不是未来的现实时间。系统不会保存尚未说出的内容，也不会在以后出现新事件时重新修改这些内容。

### DuConv 与目标导向的主动对话

[Proactive Human-Machine Conversation with Explicit Conversation Goals](https://arxiv.org/abs/1906.05572) 提出了 DuConv 数据集。对话领导者沿知识图谱路径推进，通过引入或维持话题，自然地到达预设目标。后续很多主动对话研究也集中在目标规划、澄清、说服、推荐、情感支持和任务完成。

[2023 年主动对话系统综述](https://arxiv.org/abs/2305.02750)主要将主动性定义为创造或控制对话，并预期对用户产生的影响。例如 [ProactiveEval](https://aclanthology.org/2026.acl-long.1906/)（ACL 2026）主要评价跨领域的目标规划和对话引导能力。

这些研究证明“AI 可以掌握对话主动权”不是新的主张。但它们通常仍保留回合制假设：主动策略改变的是下一条回复的内容和方向，而不是把未来表达建模成一个可以随现实时间变化的计划。

## 2. 轮次选择、等待和回复时机

这一研究路线与“即时通信不是严格的一进一出协议”更接近。

### When to Talk

[When to Talk](https://arxiv.org/abs/1912.09879) 在开放域对话模型中增加了决策模块。如果最后一句话来自聊天机器人，模型可以判断是继续说还是保持沉默。研究者修改对话数据以表示空轮次，并同时评价回复生成质量和说话/沉默判断的准确性。

这项研究确认了一个重要前提：聊天机器人不必等用户再次发言后才能继续说话。但它的判断发生在一个正在进行的多轮会话内，没有规划数分钟或数小时后的消息，也没有在用户中途插入新消息时统一整理的持久队列。

### Wait, I'm Still Talking!

[Wait, I'm Still Talking!](https://arxiv.org/abs/2002.09616) 与 Proactive AI 从同一个即时通信现象出发：人们经常把一个完整意思拆成几条短消息发送。它的 Imagine-Then-Arbitrate 模型分别想象用户和 Agent 下一步可能说什么，然后由仲裁器决定应该继续等待用户，还是立即回答。

这项工作与 Proactive AI 的输入侧尤其相关：它判断用户发来的一条或多条消息是否构成了完整表达。但它不生成数量可变、分别具有未来发送时间的 AI 输出消息。

### X-TURING 与 burst dialogue

[X-TURING](https://aclanthology.org/2025.acl-long.293/) 直接突破了一轮只能发送一条消息的惯例。它在长期图灵测试中允许用户与回答方都连续发送多条消息，为每条消息标注时间戳，并要求生成的消息组模仿人类发送间隔。因此，它是目前在可见对话文本形式上与 Proactive AI 最接近的公开工作。

但它的主要目的在于评测和构造伪对话，时间戳存在于生成文本中。论文没有定义在线调度器来持久化多项未发送行动、在各项行动到期时唤醒，或在用户新输入改变上下文时原子化取消这些行动。因此，Proactive AI 不能把“多条连续输出”本身作为创新点；更窄的贡献应当是支撑这种输出的执行与重新规划语义。

### 回复时间与全双工对话

[Neural Generation of Dialogue Response Timings](https://aclanthology.org/2020.acl-main.221/) 学习语音回复延迟的分布，并证明根据上下文调整时间比固定延迟更自然。较新的系统，例如微软的 [RESPOND](https://www.microsoft.com/en-us/research/publication/respond-responsive-engagement-strategy-for-predictive-orchestration-and-dialogue/)，会在用户尚未说完时持续判断何时给出简短回应，以及何时主动取得发言权。

这些系统研究同步语音交流中的精细时序。Proactive AI 研究的是跨越数秒、数分钟、数小时或数天的异步文字对话，其中可能长时间没有任何一方占据对话轮次。

## 3. 时间感知与持续存在的 Agent

### GapChat

[Mind the Gap Between Conversations](https://arxiv.org/abs/2310.15415) 提出了 GapChat。不同会话之间存在从短时间到数月不等的模拟间隔；模型可以看到经过的时间、之前讨论的事件以及事件在这段时间内预期发生的进展。人工评价显示，时间感知可以提高话题相关性和信息价值。

GapChat 证明了时间流逝具有语义意义，但模型仍然在新会话开始后才被调用。时间本身不会唤醒 Agent，也不会让它创建、修改或发送待执行的话语。

### Generative Agents

[Generative Agents](https://arxiv.org/abs/2304.03442) 将记忆流、检索、反思和规划结合起来，在模拟小镇中产生具有可信行为的 Agent。25 个 Agent 会按照日程行动、观察彼此、形成关系并主动开始对话。这是“Agent 在时间中持续存在，并且不依赖用户直接提示也能行动”的重要先行工作。

它所规划的单位是模拟环境中的一般行为。Proactive AI 则把问题收窄到一个持续的人与 AI 消息关系，并把尚未执行的语言行动变成显式、可查看和可修改的对象。

## 4. 持续内部思考与主动参与

学术上最接近的工作是发表于 CHI 2025 的 [Proactive Conversational Agents with Inner Thoughts](https://arxiv.org/abs/2501.00383)，以及公开的 [thoughtful-agents](https://github.com/xybruceliu/thoughtful-agents) 框架。

它的框架包含五个阶段：

1. 触发思考过程；
2. 检索相关记忆与上下文；
3. 形成候选想法；
4. 评价表达这些想法的内在动机；
5. 决定是否参与以及如何参与。

其实现区分快速想法和深思熟虑的想法，把想法与记忆作为“心理对象”保存，计算其显著性和表达动机，预测发言权分配，最后选择参与者和话语。论文的形成性研究和用户实验关注多人对话中的拟人感、连贯性、智能程度与发言时机适当性。

它与“AI 可以思考但不立即说话，并且可以压住一个想法”高度重叠。主要差异是时间执行模型：公开实现处理对话事件并选择下一位发言者，但没有提供一个持久的现实时间队列，用来保存多条未来话语和重新思考事件，并在时间或对话变化时统一重排。

## 5. 工程系统与商业产品

### ProactiveAgent

开源的 [ProactiveAgent](https://github.com/leomariga/ProactiveAgent) 是目前最接近“意识起搏器”的工程实现。它会：

- 保存对话历史和用户最后一次发言时间；
- 动态计算下一次睡眠时长；
- 睡眠结束后醒来，判断现在是否值得回复；
- 设置最短和最长回复间隔；
- 在用户发来新消息时打断当前睡眠，立即重新判断，并重新计算下一次睡眠时间。

在当前公开实现中，一次肯定判断会调用一次模型，得到一个回复字符串，将其加入对话历史，并立即调用回复回调。调度器保存的是下一次醒来时间，而不是一组分别具有发送时间的未来消息。因此，它已经实现了意识起搏和用户中断机制的很大一部分，但没有实现 Proactive AI 的“零到多条可变回复计划”。

### Character.AI、Replika 与 Nomi

商业 AI 伴侣已经证明主动联系是一种实际存在的产品行为：

- [Character.AI Away Messages](https://blog.character.ai/ama-recap-and-january-2024-faq/) 可以在用户不使用应用时由 Character 主动发送消息；
- [Replika 通知](https://help.replika.com/hc/en-us/articles/360027515872-How-do-I-set-up-my-app-s-notifications)可以包含基于过往对话的问候或跟进；
- [Nomi Proactive Messaging](https://wiki.nomi.ai/When_Your_Nomi_Messages_You_First)允许用户选择大致联系频率；如果用户没有回复，间隔可以逐步延长，并且有免打扰时间。

这些产品在用户体验层面已经与本项目有所重叠。但是，公开材料没有说明消息是否提前生成、是否有多条未来消息共享同一个队列，以及用户新输入是否会原子化地重排所有待发送内容。它们证明“主动发消息”本身不能构成论文创新点，但仍然留下了对透明、可形式化和可评价的调度模型进行研究的空间。

## 最准确的区别

最接近的现有设计可以概括为：

```text
轮次选择模型：
  当前上下文 -> 现在说话或等待

起搏型 Agent：
  睡眠 -> 醒来 -> 现在说话或等待 -> 决定下一次睡眠

Proactive AI：
  任意事件 -> 重新整理一个持久的未来表达计划
           -> 当前发送零到多条消息
           -> 修改零到多个未来行动
           -> 安排下一次思考
```

Proactive AI 的队列至少包含两种行动：

```json
{
  "actions": [
    {
      "type": "send_message",
      "content": "我又想到一件事。",
      "not_before": "2026-07-31T15:02:00+08:00"
    },
    {
      "type": "reconsider",
      "reason": "检查这个话题是否仍然值得跟进",
      "not_before": "2026-07-31T20:00:00+08:00"
    }
  ]
}
```

对于间隔很短的连续消息，可以提前准备内容；对于较长的延迟，使用 `reconsider` 可以避免过早确定可能过时的措辞。用户的新输入可以在执行前使任何一种行动失效。

## 对论文定位的影响

以下主张已经不足以构成创新：

- AI 可以主动引导对话；
- AI 可以在没有用户新消息时主动联系；
- AI 可以选择沉默；
- AI 可以延迟回复；
- AI 可以表示多条连续、带时间戳的消息；
- AI Agent 可以周期性醒来；
- 记忆可以支持长期对话。

仍可能成立的候选贡献是：

> 为异步大模型对话提出统一的事件驱动模型，将尚未说出的内容建模成第一类、可变的时间行动，并允许每条用户新消息、每次周期醒来和每个到期行动共同重新规划未来表达。

论文应该验证这套架构，而不是依赖“历史上第一次”的宣传。适合比较的基线包括：

1. 用户每发一条消息就立即回复一次；
2. 能够等待或回复的轮次判断模型；
3. 周期醒来、每次最多立即回复一条的起搏型 Agent；
4. 消息生成后不可修改的延迟队列；
5. 完整的事件驱动可变队列。

关键评价指标包括：过早插话、过时消息比例、取消准确率、回复时机适当性、对话连贯性、感知连续性、有用程度、打扰程度、用户控制感、唤醒频率和推理成本。

>
> **Proactive AI：从轮次到可重排的对话时间线**
